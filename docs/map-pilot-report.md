# Отчёт по пилотным source-тайлам Москвы и Санкт-Петербурга

Отчёт фиксирует воспроизводимую конфигурацию и результаты задачи MAP-S3-11 на
11 сентября 2026 года. Исходные PBF и staging лежат в игнорируемом каталоге
`work` и не входят в репозиторий.

## Конфигурация

- Публичный bucket: `street-racer-maps-legionersv` в каталоге Yandex Cloud
  `dqs`, класс `STANDARD`, лимит 1 ГиБ, versioning выключен.
- Публичны только чтение объектов и `GET`/`HEAD` CORS с origin
  `https://legionersv.github.io`, `http://127.0.0.1:4173` и
  `http://localhost:4173` для локальной проверки production-сборки; listing,
  чтение конфигурации и запись не публичны.
- Клиентский URL: `https://storage.yandexcloud.net/street-racer-maps-legionersv`.
- Общая сетка: XYZ z15, прямоугольник 10 × 10, halo 300 м, concurrency 4.
- DEM: Tilezen Terrarium, локальный общий кэш, снимок
  `2026-09-11T00:00:00.000Z`; условия и атрибуция зафиксированы в
  [документации Tilezen](https://github.com/tilezen/joerd/blob/master/docs/attribution.md).
- Точные координаты, dataset ID, PBF checksum и специальные клетки находятся в
  `scripts/map-pilot-config.ts` и проверяются тестом.

## Воспроизведение

Для Windows использован переносимый `osmium-tool 1.19.0` (libosmium 2.23.1) в
`%LOCALAPPDATA%\street-racer-tools\osmium`. Официального готового Windows EXE у
проекта нет; пакет conda-forge распакован переносимо через micromamba, без
Miniforge и без изменения проекта. Установка занимает около 85 МиБ.

Сначала запускается `generate:map-tiles` с `--dry-run`, затем та же команда без
флага. Для каждого города передаются его `--center`, явные `--extra-tile`, PBF,
общие каталоги `--osm-cache` и `--dem-cache`, provenance из конфигурации,
`--generated-at 2026-09-11T14:05:34.000Z`, `--concurrency 4` и полный путь в
`--osmium`. Генератор не обращается к Overpass. Повтор без `--download-dem`
полностью использует локальные OSM/DEM-кэши.

Локальная проверка и безопасный план публикации:

```powershell
npm run verify:map-pilot -- .\work\map-pilots\moscow
npm run verify:map-pilot -- .\work\map-pilots\saint-petersburg

npm run publish:map-tiles -- --staging .\work\map-pilots\moscow --dataset-id moscow-pilot-20260911 --endpoint https://storage.yandexcloud.net --bucket street-racer-maps-legionersv --dry-run
npm run publish:map-tiles -- --staging .\work\map-pilots\saint-petersburg --dataset-id saint-petersburg-pilot-20260911 --endpoint https://storage.yandexcloud.net --bucket street-racer-maps-legionersv --dry-run
```

Ключ публикации создан для service account `dqs-s3-worker` и сразу помещён в
Yandex Lockbox без вывода значения в консоль и без записи в проект. Прочитать
payload вручную можно командой (она выведет значения на экран):

```powershell
yc lockbox payload get e6qr950hulbg7f5js79n
```

Для скрипта безопаснее загрузить значения только в память текущего PowerShell,
передать их дочернему процессу и сразу удалить переменные окружения:

```powershell
$payload = yc lockbox payload get e6qr950hulbg7f5js79n --format json | ConvertFrom-Json
$env:AWS_ACCESS_KEY_ID = ($payload.entries | Where-Object key -eq 'access_key_id').text_value
$env:AWS_SECRET_ACCESS_KEY = ($payload.entries | Where-Object key -eq 'secret_access_key').text_value
try {
  npm run publish:map-tiles -- <параметры>
} finally {
  Remove-Item Env:AWS_ACCESS_KEY_ID, Env:AWS_SECRET_ACCESS_KEY
  Remove-Variable payload
}
```

Ранее существовавший статический ключ service account не изменялся и не
удалялся: его секрет нельзя повторно получить через API, поэтому новый ключ
хранится отдельной активной версией Lockbox.

Lockbox хранит одну активную версию. По тарифу на дату отчёта это около
19,73 ₽/месяц (`720 × 0,0274 ₽`) плюс 3,79 ₽ за каждые 10 000 операций чтения;
см. [официальный тариф Lockbox](https://yandex.cloud/ru/docs/lockbox/pricing).

## Стоимость и ограничения

При текущих 78,5 МиБ ожидаемая стоимость пилота — 0 ₽ в месяц, пока аккаунт не
исчерпал общий free tier Object Storage: 1 ГиБ `STANDARD`, 10 000 операций
записи, 100 000 операций чтения и 100 ГиБ исходящего трафика в месяц. После
free tier хранение `STANDARD` стоит 2,376 ₽ за ГиБ-месяц, исходящий трафик сверх
100 ГиБ — 1,67994 ₽ за ГиБ. Актуальные правила приведены в
[официальной документации Yandex Cloud](https://yandex.cloud/ru/docs/storage/pricing).

Пилоты не являются полным покрытием городов. За их границами клиент использует
существующий Overpass+DEM fallback. Качество зависит от полноты OSM и исходного
DEM; игровые сглаживание рельефа и интерпретация сложных развязок проверяются
отдельно от совпадения исходных данных на швах. Текущая фоновая подгрузка после
добавления тайлов перестраивает весь удерживаемый мир: два последовательных
обновления Петербурга заняли 28,589 и 31,725 с. Устранение этой известной
причины задержки относится к MAP-S3-12/13 (стабильные ID и инкрементальный
`WorldPatch`).

## Браузерная проверка

Проверка выполнена в production-сборке GitHub Pages локально на origins
`http://127.0.0.1:4173` и `http://localhost:4173`. Второй origin дал отдельное
пустое IndexedDB для холодного запуска. Workflow Pages передаёт тот же bucket
через `VITE_MAP_TILE_BASE_URL`; публикация самой новой сборки на GitHub Pages
произойдёт после отдельно разрешённых commit/push.

Холодный старт Москвы загрузил 16 из 16 стартовых тайлов из S3. В журнале у
каждого тайла есть `source=s3`, а `overpass-dem` отсутствует. Общий старт занял
28 216 мс: данные района — 14 460 мс, `buildWorld` — 12 972 мс, импорт движка —
977 мс, Havok — 29 мс, сцена — 113 мс, подготовка/установка стартового chunk —
75/550 мс.

| Этап одного S3-тайла | p50 | p95 | max |
| -------------------- | --: | --: | --: |
| HTTP fetch, включая browser Brotli | 225 мс | 655 мс | 655 мс |
| JSON/base64 decode и валидация | 159 мс | 319 мс | 319 мс |
| IndexedDB save       | 334 мс | 660 мс | 660 мс |

Мир Москвы собран из 170 487 уникальных OSM-объектов: 22 569 дорожных рёбер,
6 141 здания, 13 мостов и 21 тоннель. Санкт-Петербург открылся с 107 244
уникальными объектами: 22 904 ребра, 2 963 здания, 50 мостов и 38 тоннелей.
Полностью холодный старт Петербурга на отдельном browser origin загрузил 16 из
16 стартовых тайлов с `source=s3`, без `indexeddb` и `overpass-dem`, и занял
31 585 мс: данные — 13 060 мс, `buildWorld` — 17 359 мс. Для его тайлов
fetch p50/p95/max составил 337/828/828 мс, decode — 127/162/162 мс, IndexedDB
save — 281/339/339 мс. Повторный старт использовал IndexedDB.

После исправления учёта общих halo-объектов завершились два фоновых расширения
окна Петербурга, каждое на четыре S3-тайла:

| Обновление | Fetch | buildWorld | Commit | Всего | Тайлов после |
| ---------- | ----: | ---------: | -----: | ----: | -----------: |
| 1          | 6 904 мс | 20 867 мс | 156 мс | 28 589 мс | 20 |
| 2          | 6 485 мс | 23 563 мс | 207 мс | 31 725 мс | 24 |

Автоматический автопроезд, телепорт к мосту и телепорт к тоннелю не выявили
разрывов геометрии; машина оставалась на физической поверхности после
завершения тестов. Дополнительно на фоне был запрошен XYZ за границей пилота:
диагностика зарегистрировала `source=overpass-dem`, что подтверждает реальный
fallback на отсутствующей в S3 клетке. При S3 hit этот источник не вызывался.
