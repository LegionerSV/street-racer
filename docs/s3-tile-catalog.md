# Каталог source-тайлов в S3

Клиент включает публичный S3-источник только при наличии переменной сборки
`VITE_MAP_TILE_BASE_URL`. Значение указывает на корень публичного префикса без
имени файла. Клиент запрашивает каталог по адресу
`{VITE_MAP_TILE_BASE_URL}/maps/catalog-v1.json`.

Каталог версии 1 имеет следующий формат:

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-09-10T01:00:00.000Z",
  "activeDatasets": ["moscow-2026-09-10"],
  "datasets": [
    {
      "datasetId": "moscow-2026-09-10",
      "schemaVersion": 1,
      "tileBuildVersion": "2026-09-09-source-tile-1",
      "path": "maps/v1/2026-09-09-source-tile-1/moscow-2026-09-10",
      "tiles": {
        "15/19808/10243": {
          "bytes": 123456,
          "checksum": "crc32:1234abcd"
        }
      }
    }
  ]
}
```

`activeDatasets` задаёт порядок поиска среди неизменяемых наборов. Указанный в
записи тайла необязательный `path` переопределяет стандартный путь
`{dataset.path}/{z}/{x}/{y}.tile.json.br`. `bytes` содержит размер опубликованного
сжатого объекта, а `checksum` — контрольную сумму декодированного
`TileArtifactV1`.

Каталог читается один раз на игровую сессию и используется всеми повторно
созданными цепочками источников. Неуспешное чтение не кэшируется навсегда:
следующая фоновая попытка может получить уже атомарно обновлённый каталог.
Заявленный каталогом тайл загружается одним `GET`, без предварительного `HEAD`.
Ответ с `Content-Encoding: br` или `gzip` распаковывается браузером до проверки
JSON и checksum.

Без переменной `VITE_MAP_TILE_BASE_URL`, при отсутствии тайла в каталоге и при
ошибке S3 клиент продолжает существующую цепочку через Overpass и DEM. В
клиентской конфигурации не нужны и не должны присутствовать ключи Yandex Cloud.
