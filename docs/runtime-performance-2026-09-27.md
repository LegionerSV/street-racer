# Оптимизация кадра без изменения качества

Физика и решения трафика продолжают работать с шагом 1/60 секунды. Вращение колёс накапливается за все шаги, а положение колёс и состояние фонарей обновляются один раз после физики, перед отрисовкой. Геометрия, плотность потока, дальность видимости и настройки теней сохранены.

Основной поток использует компактный индекс дорог и зданий. Полный индекс с масками тротуаров, пересечениями и объединением проезжих частей остаётся в worker, где создаётся геометрия. При подготовке следующего мира переиспользуются сегменты неизменённых объектов Edge. Пространственные ячейки собираются заново под новое покрытие; это не полный инкрементальный пересчёт геометрического индекса. Новый индекс публикуется только после завершения подготовки.

Экземпляры одинаковых деталей машин с общей геометрией и материалом используют общий исходный меш, в том числе между разными цветами кузова. Краска разных цветов остаётся отдельной. Детали, материалы и число треугольников не сокращаются.

Пул хранит максимум 32 неактивные машины с их физическими телами. При скрытии отключаются узлы сцены, маски столкновений, события и синхронизация тела; сбрасываются скорости. Тело возвращается в доступный пул только после завершения следующего шага физики, чтобы Havok исполнил старую цель движения, пока машина скрыта. При повторном использовании восстанавливаются маски, положение, вращение, фонари и обработчик текущего владельца. Старейший свободный объект удаляется при переполнении. Пул очищается вместе с Traffic.

## Локальный контрольный замер

Команда PowerShell:

```powershell
$env:STREET_RACER_PROFILE = '1'
npx vitest run scripts/runtime-performance-profile.test.ts
```

Результат записывается в `outputs/runtime-performance-profile.json`. Тест запускается вручную: временные показатели не используются как нестабильный порог CI.

На синтетической сетке из 2208 направленных дорог, медиана пяти проходов:

| Операция | Время |
| --- | ---: |
| Полный геометрический индекс | 285 мс |
| Компактный индекс физики | 138 мс |
| Компактный индекс при изменении одной дороги | 142 мс |

Для шести седанов разных цветов число исходных групп инстансинга сократилось со 108 до 23. В каждой машине осталось 13246 треугольников. Группы инстансинга — не итоговое число draw calls сцены: на него также влияют видимость, тени и дополнительные проходы.

Это замер отдельных операций в Node/NullEngine, не FPS браузера и не повтор пользовательского маршрута. Особенно важно проверить проезд через границы карты, плотный поток, столкновения и повторное появление машин.

## Диагностика кадра

Экспорт производительности содержит `cpuWork`: количество кадров, среднее время и p95 в миллисекундах для:

- `physics` — все шаги физики за кадр, включая трафик;
- `traffic` — часть `physics`, потраченная на решения и физическое управление трафиком;
- `visuals` — обновление колёс и фонарей трафика;
- `render` — время вызова `scene.render()` на основном потоке, отдельно от `gpuFrameMs`;
- `install` — установка готовых чанков в начале кадра.

`traffic` нельзя прибавлять к `physics`: это вложенный замер. Эти секции не покрывают весь JavaScript между кадрами. Загрузка карты, камера, атмосфера и работа браузера могут давать дополнительные задержки. До первого кадра значение `cpuWork` равно `null`; нулевая длительность измеренной секции означает отсутствие измеримых затрат, а не отсутствие данных.
