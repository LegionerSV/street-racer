# Модели конкретных объектов

Каталог `catalog.json` сейчас пуст: исходные модели и обмеры не предоставлены. Наличие механизма подключения не означает, что точные модели мостов или домов уже созданы. Большеохтинский пока использует процедурную геометрию.

Каждая запись соответствует типу `LandmarkAsset` в `game/landmarks.ts`:

- `id`: уникальное имя набора; `kind`: `building` или `bridge`.
- `osm`: точные пары `type` (`way`/`relation`) и `id`. Имена улиц не используются для идентификации.
- `anchor`: широта и долгота начала координат модели. Вершины заданы в метрах: X на восток, Z на север, Y вверх. `rotation` — поворот вокруг Y в градусах.
- `near`: позиции, индексы треугольников и необязательные RGBA-цвета вершин; `far`: необязательная упрощённая модель. Текстуры внешних форматов в этом варианте не импортируются.
- `source` и `license`: обязательные источник обмеров/модели, авторство и условия использования. Проверить права и фактическую точность до включения записи.

Начальная высота здания — минимальная отметка его контура. Модель здания заменяет оболочку только на том LOD, для которого предоставлена геометрия; иначе остаётся процедурный силуэт. Модель и коллизии загружаются с кварталом. Одна запись здания должна соответствовать одной оболочке; части здания перечисляются отдельными записями.

Начальная высота мостовой надстройки — покрытие ближайшего сегмента соответствующего OSM way. Надстройка добавляется к дорожной конструкции. Отрицательные Y не допускаются: плита и опоры с проверкой проезда остаются процедурными. Перед подключением надо совместить надстройку с построенным профилем, проверить её габариты и проезд; текущий импорт не деформирует модель вдоль продольного уклона. Нельзя выдавать приблизительную надстройку за точную инженерную реконструкцию.

Повреждённые данные, отсутствующие OSM ID и записи без источника/лицензии пропускаются. Для проверки использовать `game/landmarks.test.ts`; синтетическая тестовая модель не входит в рабочий каталог.
